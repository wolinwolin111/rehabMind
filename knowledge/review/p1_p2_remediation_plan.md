# P1 / P2 内容整改实施方案

状态：方案，待内容审订；2026-09-29。基于 `RehabMind_LowerLimb_KnowledgeDB_v3.4.xlsx`、资产包设计文档、`10_Governance`、当前接口及页面。此文件不修改原始工作簿或运行时临床内容。

## 共同原则

- 面向有基础的康复师：主页面保留检查对象、简短检查要点、可观察的表现和处理方法名称；详细操作与文献放独立资料库。
- 保留 `Region → ClinicalItem → Finding → Intervention` 的现有结构。`CORE` 是跨模块的真实语义复用；相同文字并非自动等于重复错误。
- 由康复师决定检查结果、方法选用和安排。页面只列参考，不根据文字自动诊断、处方或确认 Finding。
- 临床内容在工作簿审订；页面只控制标题、分层和展开，不另写一套临床结论。任何新方法名称经专业审核后进入数据源。

## P2：数据维护与内容分工

### P2-A 精简过长的检查说明

`02_ClinicalItem.check_focus` 共 109 条，**16 条超过 80 字**，其中 **8 条超过 100 字**，**2 条超过 150 字**。字数只用于排查，不是自动删除标准；安全提示不能因为稍长就截断。

| 批次 | 单元格 / ID | 动作 |
| --- | --- | --- |
| 第一批：明显像操作教程或混入规则 | `D2` `CORE-ROM-ANK-DF`、`D41` `CORE-CAP-PF`、`D11:D12` 腓肠肌/比目鱼肌、`D67` 股直肌、`D92,D94` 膝伸/膝屈能力、`D109` 髋内收能力 | 逐项从原文提炼一句到两句“看什么”；体位、测量标志、补充测试条件和详细理由复制到 `knowledge/library/drafts/` 待审资料，保留原 ID 与来源。主工作簿 `check_focus` 待审稿通过后再替换。 |
| 第二批：81–100 字的边界项 | `D42:D44` 足踝外翻/内翻/背屈能力、`D66` VTE 安全筛查、`D71:D73` 股二头肌/半腱肌/半膜肌、`D93` 股四头募集 | 人工判断是否真的影响阅读；必要时才精简。安全筛查优先保留关键信息，不能机械套字数限制。 |

资料库条目只承接解释和操作，不反向驱动思路页，也不因放进目录就自动公开。对每项保存原文、拟改短句、资料库去向与审核状态，以便核对未丢失内容。

### P2-B 膝区域中文标题归源

`01_Region!D14:D28` 的 15 条膝区域目前存 `PAT_*` 或 `L3-KNEE-*` 代码；运行时由 `scripts/region_labels.json` 给出中文。先逐项核对这 15 个 ID 的现有中文定位名，再把核准标题写入工作簿 `l3_region`。之后让 `scripts/generate_knowledge.py` 和 `api/resolver.mjs` 直接读取该字段，更新相应测试；不再维护第二份同义标题。`region_id`、3D 定位映射和区域关系都保持不变。验收：15 个膝区域的数据库标题与页面一致，代码 ID 不在用户界面出现。

### P2-C 历史/内部条目分开登记

- `02_ClinicalItem!A16:D16` `AF-MUS-012` 为 `UI_ONLY`，当前未被区域映射引用。先核对资产包是否仍需要这条分组数据；若只供内部维护，保持不进入公开评估列表，并移走 `check_focus` 中的 UI/Finding 开发语言。不要为消除“孤立”而强行连到临床 Finding。
- `07_ContextRule!A18:A26` `K-CHAIN-001:009` 的 `source_context=Knee`、target 为空，当前模块入口不选择这些规则。与设计/旧版本核对后标记历史归档或迁移为有效规则；迁移必须有实际检查目标，不能仅改前缀使空规则暴露。验收：当前可选规则无空目标、无重复历史内容；被保留的旧记录有明确内部用途。

### P2-D 来源追溯

`09_Evidence` 共 68 条（55 条 URL 形式、13 条既有语料/本地描述），处理方向表和映射表没有直接证据 ID。为避免扩展核心数据库，可先在 `knowledge/review/` 建内部对照清单，按 `ClinicalItem`、`Finding`、`Intervention` 的稳定 ID 记录引用、核验日期、审核状态；资料库正式条目再引用此清单。只对**实际新增或改写的临床方法**优先补来源，不要求一次性为全部既有记录造证据，也不把长文献塞进主思路表。验收：每条新公开方法可追溯到审核记录；未审核草稿不会出现在页面。

## 执行顺序

1. 先完成 P1 的膝关节文字对照稿与处理方向样本，供康复专业审核；通过后再改工作簿及接口显示类别。
2. 用相同准则复核踝足、小腿、大腿，保持 CORE 复用和所有映射关系。
3. 做 P2 第一批长文拆分及膝标题归源；历史记录和来源追溯同步登记，但不阻塞已经审过的 P1 文案。
4. 最后核对数据库生成、映射完整性和手机端展开显示；任何临床内容变更均由数据源生成，不由页面临时改写。
