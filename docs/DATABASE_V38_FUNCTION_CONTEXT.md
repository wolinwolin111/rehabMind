## 展示与内容

维度编号保持原值，`CAPACITY` 展示为“力量与募集”，`FUNCTION` 展示为“功能动作”。

膝部对外展示改为五个动作模式：步态与支撑、双腿负重模式、单腿动作控制、落地缓冲与稳定、减速与转向控制。原十个动作条目保留为 Internal，退出展示与线索关联。

每个模式有一句目的、一句观察重点、具体表现及方法清单。相关动作是观察载体，不是一套必须完成的测试；使用场景不限定门诊，康复师可结合现场动作或已有视频观察。没有测试阈值、训练剂量、自动测试准入或自动选择方案。原通用动态控制项目及其历史内容仍保留，退出部位展示映射。

五个公开动作模式共 16 条发现和 16 组处理参考，复用原发现分类与知识主链。前一版 23 条动作发现和方法保留作内部记录。四个新接通的关联项目增加短文案：机械表现检查、远端神经筛查、髋关节活动、踝背屈活动。筛查项目不强制生成普通处理参考。

| 动作线索 | 出现的功能观察 |
| --- | --- |
| 步行、跑步 | 步态与支撑 |
| 下蹲 | 双腿负重模式 |
| 上台阶、下台阶、单腿下蹲 | 单腿动作控制 |
| 跳跃／落地 | 落地缓冲与稳定 |
| 急停／变向 | 减速与转向控制 |

没有动作线索时，功能动作只显示选择线索的入口，不列动作清单。持续活动后不适本身不推断具体动作、不展开步行或跑跳全套。多个线索对应同一模式时只显示一张卡片，保留全部关联来源。动作线索不是动作异常的检查结果。

新增临床文案的状态为“待临床审核”。来源包括髌股疼痛指南、ACL重建术后康复指南、膝痛与活动受限指南。具体动作表现及练习对应是产品编辑整理，不能把参考指南理解为验证了每条对应关系。来源范围和说明保存在证据表及扩展库内部字段，不展示在卡片正文。原有临床内容的名称、发现描述和方法未批量改写。

## 数据结构

新增 `11_ContextItemMap`：`map_id / rule_id / clinical_item_id / status`。一条线索关联多个项目，一个项目可关联多条线索，禁止重复关联。

`07_ContextRule` 新增：

- `module_codes`：明确适用模块，多个代码以 `|` 分隔。
- `public_note`：可选、数据库维护的简短公开提示，目前用于持续活动前后比较。

规则类型仍使用 `MOVEMENT / SYMPTOM / CHAIN / SAFETY / PROFILE`。普通线索的项目关联只读取新表；`target` 保留迁移历史，不再参与项目解析。PROFILE 的考虑内容继续读取原字段，SAFETY 保持原路径。

部位—项目映射仍由 `05_RegionClinicalMap` 保存。五个动作模式各保留一个膝模块的 LINKED 展示位置，通过既有解析器在同模块内按明确线索取用，不给每个膝区域复制五份。已有检查保持原分组。缺失的关联入口补充为 LINKED，未选线索时不显示。

其他模块已有的明确项目关联也迁移到新表，保留其内容和原行为；没有可执行项目目标的历史规则仍不作为可选项，迁移对照中可查。

## 接口与页面

元数据返回数据库配置的模块名称和线索适用模块。解析器按模块范围验证线索，不依据编号前缀，也不跨模块随意借用展示位置。

每个项目返回 `context_sources`，包括线索编号、公开名称和可选提示。页面显示各方向关联数量、项目的“关联线索”，并把相关补充项目移到组内可见列表。不会自动打开卡片、改变当前方向或替用户判定检查结果。

取消线索后恢复原关联状态。多个线索合并时项目去重，保留多个来源。

## 后续增加部位

1. 在 `10_Governance.module_labels` 注册模块代码和名称。
2. 增加区域、检查项目、部位映射、发现及相应临床扩展内容。
3. 增加规则适用范围和线索关联记录。
4. 生成脚本校验编号、范围及展示可达性，不限制固定区域或项目数量。
5. 页面和普通线索解析沿用现有结构。
6. 新部位的模型定位区域、定位契约和相应定位代码仍需另行补充；本轮未开发脊柱或上肢定位。

共享项目仅在临床含义一致时复用。保留已有共享记录，不新建模板继承引擎，不把下肢内容直接套到上肢。
